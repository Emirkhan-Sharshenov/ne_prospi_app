# Публикация в Google Play — что делать по шагам

Всё, что можно было сделать в коде, уже сделано. Ниже — то, что делается руками в Play Console.
Формулировки для анкет можно копировать как есть.

---

## 1. Что загружать

| Файл | Куда |
|---|---|
| `NeProspi-release.aab` | Play Console → Production (или Closed testing) → Create release |
| `NeProspi.apk` | только для проверки на своём телефоне, в Play не грузится |
| `store/feature-ru.png` (и `-en`, `-ky`) | Store listing → Feature graphic, 1024×500 |
| `app/src/main/ic_launcher-playstore.png` | Store listing → App icon, 512×512 |
| `store/listing-ru.md` (и `-en`, `-ky`) | тексты карточки, уже уложены в лимиты |

Собирать: `build-release.bat`.

## 2. Аккаунт разработчика

- Регистрация: 25 $ разово, нужен документ, удостоверяющий личность.
- **Личный аккаунт, созданный после ноября 2023:** перед публикацией нужно закрытое
  тестирование — минимум 12 тестировщиков, которые остаются подписанными 14 дней подряд.
  Это самый долгий пункт, начинать стоит сразу: Closed testing → создать список из 12 почт
  Google, дать им ссылку, попросить установить и не удалять две недели.

## 3. Подпись

Выберите **Play App Signing** (по умолчанию). Наш ключ становится ключом загрузки:

- файл: `C:\Users\user\ne-prospi-keys\nesprosi-release.jks`
- алиас: `nesprosi`
- пароль: лежит в `keystore.properties` и в резервной копии рядом с ключом

Ключ нельзя терять: без него в Play не встанет ни одно обновление. Скопируйте папку
`ne-prospi-keys` в облако или на флешку.

## 4. Политика конфиденциальности

## 5. Data safety (раздел «Безопасность данных»)

Отвечать так:

- Does your app collect or share any of the required user data types? → **Yes**
- Location → **Approximate location** и **Precise location**:
  - Collected: **Yes**, Shared: **No**
  - Processed ephemerally: **Yes** (координаты не сохраняются на сервере)
  - Required for the app to function: **Yes**
  - Purpose: **App functionality**
- Personal info → Phone number (только если пользователь сам ввёл номер близкого):
  Collected: **No** — номер не покидает телефон и никуда не передаётся.
- Data encrypted in transit: **Yes** (запросы к OpenStreetMap идут по HTTPS)
- Users can request data deletion: удаление приложения удаляет все данные.

## 6. Анкеты по разрешениям

**Exact alarms (`USE_EXACT_ALARM`)**
> Приложение является будильником. Пользователь задаёт страховочный таймер, который должен
> сработать точно в назначенную минуту, даже если телефон спит и GPS недоступен.

**Full screen intent (`USE_FULL_SCREEN_INTENT`)**
> Будильник должен показывать экран с кнопкой отключения поверх экрана блокировки, как
> обычный будильник, потому что пользователь в этот момент спит.

**Battery optimisation exemption (`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`)**
> Без исключения система усыпляет приложение во время поездки, и будильник не срабатывает.
> Разрешение запрашивается только перед поездкой, работу без него приложение не блокирует.

**Foreground service — тип `location`**
> Во время поездки приложение считает расстояние до остановки по GPS при выключенном экране.
> Служба запускается только после нажатия «В путь» и останавливается, когда поездка окончена.

**Foreground service — тип `mediaPlayback`**
> Тип используется, когда служба проигрывает звук будильника. Он нужен как запасной путь:
> если систему разбудил страховочный таймер после того, как приложение было выгружено из
> памяти, доступ к GPS из фона может быть недоступен, и служба запускается ради звука.

Для типов службы Play просит короткое видео: снимите экран телефона — выбор точки,
нажатие «В путь», экран поездки при выключенном экране, звонок будильника.

## 7. Остальные разделы App content

- **Ads:** нет рекламы.
- **App access:** весь функционал доступен без входа, логина нет.
- **Content rating:** анкета → категория «Утилиты», насилия/пользовательского контента нет →
  рейтинг 3+.
- **Target audience:** 13+ и старше, приложение не для детей.
- **Government app / Financial features / Health:** нет.
- **Category:** Maps & Navigation (или Travel & Local). Теги: alarm, transit, navigation.
- **Contact email:** будет виден всем в карточке приложения.

## 8. Скриншоты

Нужно минимум 2 (лучше 4–8) скриншота телефона, 16:9 или 9:16, не меньше 320 px по короткой
стороне. Снять с телефона:

```
adb exec-out screencap -p > store/shot-1.png
```

Хорошие кадры: карта с выбранной точкой, панель «когда будить», экран поездки, экран
будильника, настройки.

## 9. Чего в приложении сознательно нет

- Нет разрешения `SEND_SMS`: Play выдаёт его почти только приложениям-мессенджерам по
  умолчанию. Сообщение близким готовится и отправляется вашим обычным SMS-приложением
  в одно нажатие.
- Нет `ACCESS_BACKGROUND_LOCATION`: самая строгая проверка Play, приложению оно не нужно —
  геопозиция берётся только во время активной поездки.
